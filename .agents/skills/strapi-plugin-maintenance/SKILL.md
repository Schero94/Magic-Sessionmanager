# Magic-Sessionmanager maintenance

Use Node 22. Read the always-applied Strapi plugin rule and check current Strapi 5 docs through Context7 before using admin or Design System APIs. Compare with installed types and the pinned workbench version. If Context7 is quota-limited, tell the user and verify official docs plus the installed implementation. Do not embed credentials, encryption keys or browser auth state in skills, source or Git; do not push without an explicit request.

Trace `server/src/routes/admin.js`, `content-api.js`, bootstrap JWT wrapper, session services and `admin/src/permissions.js`. Make a route matrix for anonymous, unauthorised admin, allowed admin, own session and other user's session. Check revocation, session listing, settings and analytics on the server; hiding a menu is not access control. Public hooks or compatibility routes require a documented signature/token and rate limit. Verify encryption key fallback is development-only, no token/PII logging, retention and GeoIP consent/availability; do not call external GeoIP services in a smoke test.

For the admin UI, first read the workbench root `references/ui-ux-standards.md`. Use current Strapi 5 Design System components. Register a new Settings section with `app.addSettingsLink({ id, intlLabel }, links)` and add links to an existing section with `app.addSettingsLink(sectionId, linkOrLinks)`. Use permission-backed navigation, accessible controls and responsive forms. Use the Design System Switch for binary settings; in installed v2.2.4, Toggle displays Off/On choices vertically and is not the compact control. Keep the horizontal switch beside its title and description in one row. Do not stack the switch above centered copy. Use shrink-safe layouts (`width: 100%`, `min-width: 0`, responsive grid columns) and verify 320/390/1024/1440 CSS px plus the full breakpoint-adjacent matrix through Playwright CLI. Use Playwright CLI exclusively; never use CUA, Computer Use, or desktop-control tools. Preserve existing Settings routes and RBAC. If a link is missing, verify registration and the admin role before changing permissions. Run `npm test`, `npm run test:ts:front`, `npm run build`, `npm run verify`, and `npm run verify:runtime`; then shared app build, boot and authenticated Playwright CLI checks. If authentication or screenshot capture is unavailable, leave visual acceptance open. Report unit, integration, negative-permission and responsive-browser evidence separately.

For the Users & Permissions end-user panel, use the documented Content Manager API `addEditViewSidePanel` for contextual session information. Use `addDocumentAction` or `addDocumentHeaderAction` when the task is a document action. Do not depend on `editView.informations`; Strapi marks that injection zone internal. Verify the mobile ActionsDrawer after opening it, including its constrained inner scroll area and reachability of the final action. The official API references are [Content Manager APIs](https://docs.strapi.io/cms/plugins-development/content-manager-apis) and [Admin injection zones](https://docs.strapi.io/cms/plugins-development/admin-injection-zones) (checked 2026-10-16; confirm installed package types on future upgrades).

Keep Playwright CLI evidence private and value-free. Its accessibility snapshots may include values from password inputs. Check sensitive fields before snapshotting, enter fake credentials only in memory, and navigate away or clear the field before capturing another snapshot. Never reuse a test credential that appeared in CLI output or an artifact.

## Shared product quality contract

Use spec-first development: define acceptance criteria and API response/error contracts before implementation.

Every behavior change starts with a written current-state and target-state analysis covering screens, controls, routes, roles, data, known gaps and non-goals. Define acceptance criteria and API response/error contracts before implementation, then add a failing regression test first. A primary task should take no more than four meaningful user interactions from the plugin entry page; exclude login and mandatory security confirmations, and measure and document any justified exception. Use the Strapi Design System, responsive layouts, keyboard accessibility and explicit loading, empty, success and error states. Enforce authentication, plugin permissions, validation and owner boundaries server-side. Keep API error contracts consistent within each Strapi surface and never return stack traces or internal details. Do not log secrets, tokens, cookies, request bodies, email, IP or stable user/session identifiers. Use fakes for providers and record unverified behavior accurately. Magic Session Manager remains limited to Users & Permissions end-user sessions; Strapi Admin sessions are outside scope.
