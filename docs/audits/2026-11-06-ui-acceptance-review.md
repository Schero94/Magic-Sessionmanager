## API and security

API/security review for gate A2 (Magic Session Manager, snapshot of codex/sessionmanager-complete-acceptance, live host 127.0.0.1:1351 on Strapi 5.61 running the rebuilt snapshot dist). There are 21 admin routes (20 base routes plus the dev-only simulate-timeout) and 7 Content API routes. Every admin route uses admin::isAuthenticatedAdmin plus admin::hasPermissions(plugin::magic-sessionmanager.access) (server/src/routes/admin.js:41-47). Every Content API route uses the users-permissions auth strategy plus a read or write rate-limit middleware (content-api.js:20-35). No plugin route attaches the session-required policy. Live probes: all 21 admin routes returned 401 to anonymous callers, and a U&P JWT on GET /magic-sessionmanager/sessions also got 401. All 7 Content API routes returned 403 to anonymous callers. The owner got 200 on /my-sessions, /current-session and /user/<own id|docId>/sessions. Another user's id or docId got 403. Deleting another user's existing session got 403, and absent or malformed native ids got 404. No IDOR was found. Admin invalid-input cases returned 400 with the safe {data:null,error} envelope, and missing users or sessions returned 404. Settings PUT uses an allowlist, so there is no mass assignment. No PII or raw errors appear in the error bodies or logs reviewed.

## Settings (code)

I reviewed the design and UX of the Settings page and checked it in the browser. Settings.jsx was read in full (2269 lines), along with FormField, SettingsToggleRow, emailTemplateDraft, countries, geofencingMode and settingsEquality. The live check ran on 127.0.0.1:1351 at 390 and 1440 px, with an overflow pass at 320/390/768/1024/1440. Every Design System prop used (Badge backgroundColor/textColor/variant, Switch visibleLabels, Accordion.Trigger icon/description, Button loading, NumberInput onValueChange, Checkbox onCheckedChange) exists in the installed DS 2.2.4 types. All 228 literal t() keys are present in en/de/es/fr/pt, and the page has no document overflow at any tested width. Main defects: (1) "Copy for .env" produces keys that dotenv 16.6.1 cuts off at '#'. This was measured at 30.9% of generated keys and silently weakens SESSION_ENCRYPTION_KEY. (2) Two different messages share one i18n key, so the Max Failed Login Attempts field always shows the literal "{count}" in the live host. Because of this, GATES.md G7, which is marked [x], is not credible for number limits and validation states. (3) The settings form has no inline validation path. Clearing the number field shows "blocked after  failed attempts" while Save stays enabled, and typing -3 silently clamps to 0, which turns lockout off. (4) Leaving the page with unsaved changes gives no warning: in the live host, a dirty draft was dropped when navigating to Analytics. (5) Accessibility: the allowlist/blocklist mode buttons have no pressed state, the heading order jumps from H3 to H2 to H3, and there is a contrast failure in the editor header. Smaller issues: hard-coded colours, px sizes and fonts; emoji in headings; English-only aria-labels and placeholders; some German strings left untranslated; switching geofencing mode silently clears the country list; the Clean Now card is cramped at 390 px. Nothing was saved and no POST was sent: the Clean Now confirm was dismissed, and the email/webhook switches were only toggled in the unsaved draft.
